# HCM Academy

The landing page for Vanderbilt's HCM Academy: what the HCM role is, what the
Academy is for, and the topics with their courses.

Built with the Vanderbilt FLH course builder pattern, matching Working Smarter
(`me5231979/Course_Library`, `learn/index.html`): same colors, type, header,
hero, and footer. One self-contained HTML file, no framework,
no build step, no backend. Fonts and lockups live in `assets/`.

## Structure

Kept deliberately short:

1. **Hero**: what an HCM is (people embedded in the business who own the people work for their area) and what the Academy is for: learn, share, meet, get answers.
2. **Choose a topic**: a progress panel, a search box that searches every topic, and a row of horizontal topic tabs (built from the cards, so a new card gets a tab automatically; its `data-short` attribute is the tab label, and each tab shows its completed/total count). One topic shows at a time, full width, with training topics and job aids side by side. There are eight topics (Start Here plus seven topic areas). Each card, or each subsection in it, lists its training topics. 01 Positions, Recruitment & Hiring covers position management, staff hiring, and regional and out-of-state hiring (placeholder until EC provides details); 03 Assignments covers changes for current employees, transfers and promotions (requisition vs. no requisition), and offboarding; 06 holds all student and faculty hiring. Job aids are not listed separately: every course carries its own printable job aid.
   Below the cards, a one-line "HCM Playbook" strip marks where quick references will live (coming soon). Planned resource types: decision trees, process maps, scenario exercises, an FAQ, and fixes for common errors.
3. **Footer**: contact and accessibility statement.

## Assessments and completion

The assessments are their own pages, not pop-ups, so they can be linked, bookmarked, and later packaged for Oracle like the courses.

- Questions live in `assets/assessments.js` (one file for the assessment pages and the review document). Each question has a topic (the card id), the options, the correct option, optional feedback, and `draft: true` when its topic has no course yet and an SME must confirm it.
- **Pre-assessment** (`assessment/pre/`): the first row in Start Here, under "Begin here". 16 questions, two per topic, not graded. Results list the topics with a missed question, each linking to that topic's tab. The row shows "Taken" afterward.
- **Locked until the pre-assessment**: every course row shows "Locked" and points back to the pre-assessment until it has been taken once; a course page opened directly shows a locked message. Mark all complete (demo) also marks the pre-assessment taken.
- **Course completion**: passing a course's 3-question check marks it complete. Rows without a course yet are click-to-complete stand-ins.
- **Final assessment** (`assessment/final/`): the button in the progress panel links to it once every course is complete; before that, the page shows a locked message. 20 questions; 90% (18 of 20) marks HCM Academy complete. Below that, results list the topics to review and offer a retake. Answer order is shuffled each time. Pass mark: `pass` in `assets/assessments.js`.
- The assessment pages are generated by `python3 tools/build_courses.py` (same template as the courses). The build inlines `assets/assessments.js` and `assessment/assessment.js` into each page, so a cached page always has matching questions. Rebuild after editing either file.
- **Demo controls** in the progress panel: Mark all complete, Reset demo.
- Progress is saved only in this browser (`localStorage` keys `hcm-pre`, `hcm-done`, `hcm-final`, and `hcm-total`, the course count the landing page writes for the final's lock); nothing is sent anywhere.
- **Review document**: `node tools/build_assessment_doc.cjs` rebuilds `docs/HCM_Academy_Assessments_Draft.docx` from the same questions, with answers, Approve/Edit/Remove checkboxes, and notes boxes.

## Course rows

Every course, job aid, and resource is a row with a title, a one-line overview,
time (or length), format (or type), and status. Overviews, times, and formats are
placeholder estimates written for the mock-up, except formats carried over from the
current catalog (videos and e-learning). Edit them in place: each row is
`<span class="tt">Title</span><span class="ds">Overview</span>` then
`<span class="tm">Time</span>` and `<span class="fm">Format</span>`.

## Micro-courses (V.01)

79 short courses live in `courses/<slug>/`. Each has four parts: a brief intro,
a step-by-step walkthrough (a checklist where each step has a plain-language explanation
and the course ends with links to official Oracle or UKG documentation), a 3-question knowledge check with
feedback, and a printable one-page job aid (Print button; print CSS shows only
the job aid). Passing all three questions marks the course complete on the
landing page (shared `localStorage` key `hcm-done`, id `c-<slug>`).

- Every landing row is a micro-learning course (format "Micro-learning", 3 to 10 minutes).
- Courses drafted from Oracle documentation and official sources (not SME sessions) live in
  `tools/courses_researched.py`; each shows a draft note and a Screen check list until a
  Vanderbilt SME reviews it.
- Content lives in `tools/course_content.py`. Edit there, then run
  `python3 tools/build_courses.py` to regenerate every page. The script also
  updates each course's row on the landing page (name, overview, time).
- Shared look and behavior: `courses/course.css`, `courses/course.js`.
- **Videos**: to start a course with a Guidde (or other) embed, add
  `video=dict(src="<embed URL>", title="<what it shows>")` to that course in
  `tools/course_content.py` and rebuild. The video appears at the top of the
  intro (16:9, full width, hidden when printing) and the course header lists
  "Video". First one: Weekly time card check.
- **Detailed job aids**: a course can add `detailed=dict(title, source, steps=[dict(t, d, img)])`
  with screenshots in `courses/<slug>/img/`. The one-page job aid becomes the
  **Quick guide** and the detailed job aid follows it (its own print pages).
  Two print buttons: quick guide only, or both. First one: Weekly time card
  check, from Briana Knowles's Guidde walkthrough. Blur names, employee IDs,
  usernames, and assignment numbers in any screenshot before adding it; the
  site is public.
- Sources: Briana Knowles (Oct 20), Alex Enferadi (Oct 20), Jennifer Garcia
  (Oct 19) sessions; HCM training sessions 1 and 2 (Andres Castro, Stephanie Commo, Sep 8 and 9, 2026) for positions, requisitions, and pending worker conversion; the Costing for Persons guide (2022); the Document Records
  guide; the Award Compensation Elements guide (2023). Open items are flagged
  in each course's draft note and watch-outs.
- Landing rows link to a course with `data-course="<slug>"` on the `<li>`.

## Adding a course when it ships

Each course line shows "Coming soon". When a course is live, replace that
`<span class="soon">Coming soon</span>` with `<a href="courses/<slug>/">Open</a>`.

## Accessibility and brand gate

Last run 2026-10-20:

- axe-core 4.10 (WCAG 2.0/2.1/2.2 A and AA plus best practice): 0 violations at 1440x900 and at 320px.
- No horizontal scroll at 320px. Console clean.
- Keyboard: skip link works, every control reachable with visible focus; topic tabs follow the ARIA tabs pattern (arrow keys, Home, End).
- Reduced motion turns off smooth scrolling.
- Palette: approved Vanderbilt colors only. Oak (#946E24) measures 4.19:1 on Cream, so cream sections set labels in black and keep gold for ticks and rules.
- Zero em or en dashes.
